# 「小学生趣味古诗词学习网站」建设方案

> 站点载体：up999.cn（GitHub Pages，自定义域名，仓库 xasnow/up999，公开仓库，main 分支发布）
> 文档定位：本阶段仅做方案设计，不写业务代码、不提交、不部署
> 版本：v1.0（2026-11-24）

---

## 0. 现状与前提

| 项目 | 现状 |
|---|---|
| 仓库 | `xasnow/up999`，公开，唯一分支 `main`，共 3 次提交 |
| 现有内容 | 仅 1 个落地页 `index.html`（内联 CSS、无 JS）、`CNAME`（up999.cn）、`README.md` |
| 部署方式 | GitHub Pages 传统分支部署，源为 `main` 根目录（Deployments 记录 `ref=main`） |
| 域名 | up999.cn 已解析到 GitHub Pages 四个 A 记录；www 为别名；HTTPS 已生效 |
| 构建体系 | 无 package.json、无 CI、无 .nojekyll、无 404 页 |
| 本地网络 | 本机直连 github.com:443 超时，仅有文件快照；落地时需代理/镜像 |

本方案的所有技术选择，都受三条硬约束支配：

1. **站点必须部署在 up999.cn 根路径**（`https://up999.cn/...`），不引入子路径 base 的复杂度；
2. **小学生移动端优先**（家长手机打开为主），首屏要快、交互要少而明确；
3. **内容量会从 3 首增长到 100+ 首**，因此必须"数据与页面分离"，不能靠手写 HTML 堆页面。

## 1. 信息架构

### 1.1 一级菜单：按"大类"分，不按学段分（结论）

一级导航定为 4 项：

```
首页  |  唐诗  |  宋词  |  其他朝代
```

理由：

- 用户明确要求"一级按大类、大类下朝代 → 作者"，按体裁分（唐诗/宋词）最贴合这个心智模型；
- 学段（低/中/高年级）是**筛选维度**而非内容归属：同一首《静夜思》既可能被一年级孩子读，也可能被三年级孩子复习。把学段做进一级菜单会迫使我们给每首诗唯一归类，后续必然打架。因此学段做成**首页和列表页的筛选器 + 标签**，不进导航；
- "其他朝代"单独占一级，是为了满足"其他阶段古诗词预留分类位"的要求：前期展示"整理中"占位卡片，后期填充内容不需要改导航结构。

主题（思乡、送别、咏物、边塞……）同样只做标签与筛选，不占一级菜单——主题交叉严重，做导航会产生大量重复入口。

### 1.2 层级与 URL 设计（结论）

统一为**四级路径**：`大类 / 朝代（或时期） / 作者 / 作品`。

| 层级 | 示例 URL | 页面内容 |
|---|---|---|
| 首页 | `/` | 推荐、分类入口、今日一诗 |
| 大类首页 | `/tangshi/` | 唐诗总览：时期卡片、代表诗人、全部作品数 |
| 二级：时期 | `/tangshi/shengtang/` | 盛唐作者列表（按生年排序） |
| 三级：作者 | `/tangshi/shengtang/libai/` | 李白生平、年表、作品列表（按写作时间） |
| 四级：作品 | `/tangshi/shengtang/libai/jingyesi/` | 《静夜思》详情页 |

具体 slug 规划：

| 大类 | 二级（时期） | 说明 |
|---|---|---|
| `tangshi` 唐诗 | `chutang` 初唐、`shengtang` 盛唐、`zhongtang` 中唐、`wantang` 晚唐 | 四级固定，不增不减 |
| `songci` 宋词 | `beisong` 北宋、`nansong` 南宋 | 词人按主要活动年代归档 |
| `qita` 其他朝代 | `xianqin` 先秦、`hanwei` 汉魏六朝、`yuandai` 元代、`mingqing` 明清 | 首期只出占位页 |

设计要点：

- **URL 全部小写、拼音、无中文、无尾斜杠歧义**：Astro 默认输出目录式路由，`/tangshi/shengtang/libai/jingyesi/` 对应 `dist/tangshi/shengtang/libai/jingyesi/index.html`，GitHub Pages 直接可访问；
- 作品 slug 采用**全站唯一**的拼音（`jingyesi`），不强制加作者前缀。若出现同名（如多首《无题》《绝句》），用"作者 + 序号"消歧：`libai-jueju-1`、`dufu-jueju-2`；
- 作者 slug 同样全站唯一（`libai`、`dufu`、`sushi`），避免同一作者跨时期时路径变动；
- **不做纯前端路由（hash / history SPA）**。静态站每个页面都是真实 HTML，刷新、分享、被搜索引擎收录都不会 404。

### 1.3 扩展预留（结论）

| 扩展需求 | 预留方式 | 落地成本 |
|---|---|---|
| 新增朝代（如元曲、诗经） | `qita/` 下新增一个 era 数据项 + 一个目录页，导航不变 | 低，纯数据 |
| 新增体裁（如宋诗、元曲） | 新增一级 slug（如 `songshi`），复用同一套四级模板 | 中，需加导航项 |
| 新增学段/年级 | 作品字段 `gradeBand` 枚举扩展，筛选器自动出现 | 极低 |
| 新增主题标签 | 作品 `tags` 数组追加，标签页自动生成 | 极低 |
| 新增"诗人年表"页 | 作者数据增加 `timeline` 字段，详情页已有渲染位 | 低 |
| 新增音频/视频讲解 | 作品数据增加 `audio` / `video` 可选字段，前端按存在性渲染 | 低 |
| 多语言（不需要） | 不预留，避免过度设计 | — |

导航与 URL 一旦上线就应保持稳定（外链、收藏、SEO），因此**首期就把 `qita/` 空分类和四个唐诗时期页建出来**，避免后期改路径。

## 2. 内容模型

### 2.1 实体关系（结论）

四个实体，除"作品"外都可枚举，全部以 JSON 落盘，构建时校验：

```
朝代/大类 (dynasty)
   └── 时期 (era)            ← 唐诗四分、宋词两分、其他朝代若干
         └── 作者 (author)    ← 一个作者只归属一个时期
               └── 作品 (poem) ← 一首作品只归属一个作者
```

- **不建数据库**：静态站没有服务端，JSON + 构建期索引就是最合适的"数据库"；
- **作者与作品在构建期生成反向索引**：作者页的作品列表、上一首/下一首、时期页的作者列表，都由脚本自动算出，不手写；
- **作品排序字段**：`writtenYear`（写作年份，可为负/约数）+ `orderInAuthor`（同年内的次序）。按时间排序只依赖这两个字段，绝不用文件顺序；
- **拼音、译文、注释、时间线全部是作品的内嵌字段**，不拆表——一首诗的所有信息在一个文件里，便于校对和 AI 辅助生成。

### 2.2 字段设计

**朝代/大类（`src/data/dynasties.json`）**

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | string | `tangshi` / `songci` / `qita` |
| `label` | string | 显示名：唐诗 |
| `intro` | string | 大类简介（60 字内，儿童口吻） |
| `status` | enum | `live` / `coming`（`coming` 显示"整理中"占位） |
| `eras` | array | 子时期：`{id,label,sortOrder,range,intro,status}` |
| `themeColor` | string | 该大类主题色（唐=赭红、宋=青绿、其他=墨灰） |

**作者（`src/data/authors/libai.json`）**

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `id` / `slug` | string | 是 | 均用拼音，slug 全站唯一 |
| `name` / `namePinyin` | string | 是 | 李白 / lǐ bái |
| `dynasty` / `era` | string | 是 | 关联 `dynasties.json` |
| `birthYear` / `deathYear` | number | 是 | 701 / 762，未知用 `null` |
| `yearsLabel` | string | 否 | "701—762"，用于展示不确定年代 |
| `courtesyName` / `alias` | string[] | 否 | 字太白；号青莲居士 |
| `hometown` | string | 否 | 祖籍陇西成纪（今甘肃秦安一带） |
| `portrait` | object | 否 | 作者画像：`src/alt/credit`，缺省用统一剪影 |
| `summary` | string | 是 | 一句话介绍（30 字内，小学生能懂） |
| `biography` | string[] | 是 | 生平段落数组，每段 80—150 字 |
| `deeds` | object[] | 是 | 主要事迹：`{title, text, year?}`，3—5 条 |
| `timeline` | object[] | 否 | 年表：`{year, age?, event}` |
| `styleTags` | string[] | 否 | 诗风标签：浪漫、夸张、爱用月亮 |
| `funFacts` | string[] | 否 | 冷知识，增强趣味性（如"李白爱写月亮，现存诗中出现 300 多次"） |
| `poemOrderRule` | string | 否 | 默认 `writtenYear`；无系年作品排最后并标注"约作于" |

**作品（`src/data/poems/jingyesi.json`）**

| 分组 | 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|---|
| 基础 | `id` / `slug` | string | 是 | `tang-shengtang-libai-jingyesi` / `jingyesi` |
| | `title` / `titlePinyin` | string | 是 | 静夜思 / jìng yè sī |
| | `dynasty` / `era` / `genre` | string | 是 | `tangshi` / `shengtang` / `shi`（`ci` 为词） |
| | `authorId` | string | 是 | `libai` |
| | `gradeBand` | enum | 是 | `g1-2` / `g3-4` / `g5-6` / `ext`（拓展） |
| | `textbook` | string | 否 | "部编版一年级下册" |
| | `tags` | string[] | 是 | 思乡、月夜、五言绝句 |
| | `difficulty` | number | 否 | 1—5，用于推荐排序 |
| | `writtenYear` / `writtenLabel` | number/string | 是 | 726 / "约公元 726 年（26 岁）" |
| | `orderInAuthor` | number | 是 | 同年后排序 |
| 原文 | `lines` | object[] | 是 | `{text, pinyin[], translation, noteIds[]}`，**text 含标点，pinyin 按去标点后的字对齐** |
| | `form` | string | 否 | 五言绝句 / 七言律诗 / 词·水调歌头 |
| | `famousLines` | string[] | 否 | 名句，用于首页卡片 |
| 释义 | `notes` | object[] | 是 | `{id, word, pinyin, meaning, detail?}` 逐词注释 |
| | `translation` | string | 是 | 整首白话译文（儿童口吻） |
| | `appreciation` | string | 是 | 赏析，80—150 字 |
| | `pinyinNotes` | object[] | 否 | 多音字/易错音：`{char, reading, reason, standard}` |
| 讲解 | `background` | string | 是 | 写作背景（谁、何时、何地、为何写） |
| | `storyline` | object[] | 是 | 时间线讲解：`{step, title, text, imageStep?}`，3—6 步 |
| 多媒体 | `images.cover` | object | 是 | `{src, width, height, alt, credit, aiGenerated}` |
| | `images.panels` | object[] | 否 | 分镜图：`{step, src, width, height, alt}` |
| | `audio` | object | 否 | `{src, duration, narrator?}`，朗读音频 |
| 元信息 | `sources` | string[] | 是 | 教材/版本依据，如"部编版一年级下册" |
| | `status` | enum | 是 | `draft` / `reviewed` / `published` |
| | `updatedAt` | string | 是 | ISO 日期，用于"最近更新" |

约定三条硬规则（写入校验脚本）：

1. `pinyin[]` 长度必须等于 `text` 去掉中英文标点后的字数；
2. `notes[].id` 必须被 `lines[].noteIds` 引用，且不能有孤立注释；
3. `status=published` 的作品必须有 `cover`、`translation`、`storyline`、`sources`，否则构建失败。

## 4. 拼音方案

### 4.1 结论：构建时预生成、写入数据、人工校对

**不采用运行时拼音库**（如 pinyin-pro 浏览器版）。理由：

1. 多音字在运行时靠词库猜，古诗恰恰是"床前明月光""远上寒山石径斜"这类容易被猜错的语境，运行时出错无法逐条修正；
2. 目标用户是低龄儿童，**读错一个音比加载慢更严重**，必须可人工锁定；
3. 预生成后页面是纯静态 HTML，无 JS 也能看到拼音，利于首屏速度和 SEO；
4. 拼音库压缩后仍约 100—300KB，为 100 首诗引入不值得。

工具链：Node 脚本 `scripts/gen-pinyin.mjs` 调用 `pinyin-pro` 生成初稿 → 写入 JSON → 人工在 JSON 上改。**pinyin-pro 只作为离线编辑工具，不进入前端产物。**

### 4.2 多音字与"入声字"的处理

| 问题 | 处理方式 |
|---|---|
| 多音字（长/行/还/尽/为/数/重/曲/乐/更/著…） | 逐条写入 `pinyin[]`，不依赖词库；同时把易错项写入 `pinyinNotes`，页面上做"小提示" |
| 变调（一、不） | 存**实际朗读的变调读音**：`一片` → `yí piàn`、`不是` → `bú shì`；如教学需要本调，在 `pinyinNotes` 说明 |
| 轻声 | 按《现代汉语词典》词条注音，如"衣裳（yī shang）"，不强行标原调 |
| 入声字 | **不标古音**。入声在普通话中已消失（如"月 yuè、白 bái、石 shí"），小学阶段只教现代规范读音；若涉及押韵差异，仅在 `pinyinNotes` 用一句话说明，不进入正文注音 |
| 古音/押韵异读（斜 xié/xiá、见 xiàn、衰 cuī） | **以部编版教材注音为最高优先级**；教材未涉及的按《现代汉语词典》；异读只在注释里提"押韵时可读…"，正文统一用一个读音，避免孩子混淆 |
| 生僻字 | 首期选篇阶段直接规避；无法规避时增加"这个字怎么读"卡片（字形、部首、字义） |

### 4.3 标注粒度与显示

- **原文：逐字标注（ruby）**。理由：小学生遇到不认识的字是"卡在某个字"，逐字最直观；词义解释放在注释里（逐词）；
- **注释与译文：不标拼音**（避免页面过密），只有注释词本身给出拼音；
- 显示：声调符号标在韵母主元音上（`ā á ǎ à`），`ü` 在 `j/q/x/y` 后写作 `u`（如 `jǔ`）；拼音字号约为汉字 55%—60%，颜色用低对比灰蓝，避免抢主体；
- 拼音开关用 `ruby rt { display: none }` 整体隐藏，不改变行高，避免开关时页面跳动（预留 `ruby` 高度）。

### 4.4 校对流程（每条作品必过）

```
AI/脚本初稿 → ① 与教材逐字比对 → ② 人工一校（标点、变调、多音字）
→ ③ 人工二校（朗读一遍，听感校验）→ ④ 抽检（每批次 20%）→ 发布
```

落地要求：

- JSON 增加 `pinyinReview: {reviewer, reviewedAt, basis}`（本方案示例中为精简未列，实现时补上）；
- 校验脚本自动检查：音节数 = 去标点字数、拼音只含合法字母与声调、无空项；
- 建立**多音字对照表**（`src/data/pinyin-overrides.json`），记录"字 + 语境 + 正确读音"，供后续新诗复用与回归检查；
- 校对发现的错音要沉淀为规则，避免下一篇再错。

## 5. 漫画配图生产方案

### 5.1 结论：AI 生成 + 人工筛选与修整，统一风格规范

手工绘制 100+ 张成本过高且风格难统一；纯 AI 直出又会出现手指、文字、时代错乱。推荐"**AI 批量生成候选 → 人工挑选 → 局部修整 → 统一压缩入库**"，并建立风格规范与角色设定，保证跨诗一致性。

### 5.2 画风规范（写死进 prompt 模板）

- 风格：**国风儿童绘本漫画**，淡彩水墨 + 圆润线条，暖色月光，扁平化上色，轻微纸张纹理；
- 禁止：画面内出现任何文字/印章/水印（AI 中文必乱码）、现代物品（电线、塑料瓶、眼镜）、恐怖或血腥元素、真实在世画家姓名风格；
- 人物设定固定：李白 = 白袍、黑发髻、腰佩长剑、清瘦；杜甫 = 青灰长衫、瘦削、眉头微皱；儿童角色 = 圆脸、短袄；
- 构图：单主体 + 留白（方便叠加标题），视线引导到诗句关键物象（月、霜、孤舟、柳枝）。

Prompt 模板（示例，实际以英文为主、中文补充）：

```
Children's picture-book illustration in Chinese ink-wash style, soft gouache colors,
rounded friendly linework, warm moonlight, 4:3 composition, a young Tang-dynasty poet
in white robe with a sword sitting on a wooden bed in an old inn, moonlight pooling
on the floor like frost, round moon outside a lattice window, gentle night palette,
storybook mood, no text, no watermark, no modern objects --ar 4:3
```

### 5.3 数量、尺寸与命名（结论）

| 类型 | 数量 | 尺寸 | 格式 | 用途 |
|---|---|---|---|---|
| 作品封面 | 每首 1 张 | 1200×900（4:3） | WebP（q80）+ AVIF | 列表卡片、详情页头图 |
| 分镜图 | 每首 2—3 张（按 storyline 步数，最多 4） | 800×600 | WebP | 时间线讲解 |
| 作者画像 | 每位 1 张 | 600×600（1:1） | WebP | 作者页头像 |

首期 36 首按平均 3.5 张计约 **126 张**，加作者 15 张，约 **140 张**。

命名规则（与 slug 强绑定）：

```
public/assets/img/poems/{poem-slug}/cover-1200.webp
public/assets/img/poems/{poem-slug}/step-{n}-800.webp
public/assets/img/authors/{author-slug}-600.webp
```

### 5.4 生产流程

1. **批量生成**：用统一模板 + 每首诗的场景变量，一次生成 4 张候选；
2. **人工挑选**：按"是否表现诗句关键物象 / 人物是否符合设定 / 有无手指与文字错误 / 是否适合儿童"四项打分；
3. **修整**：统一色调、裁切构图、修手指、去掉疑似文字；
4. **压缩入库**：`sharp` 或 `squoosh` 批量转 WebP/AVIF，保留原图到仓库外（Git LFS 或对象存储，不进 Pages）；
5. **记录**：`docs/image-log.csv` 记录 slug、prompt、seed、工具、挑选理由，便于复现与追责。

### 5.5 加载优化与 alt

- `<img width height loading="lazy" decoding="async">`，首屏封面 `fetchpriority="high"`；
- 封面同时提供 AVIF/WebP（`<picture>`），单张控制在 **80KB 以内**（封面）/ **40KB 以内**（分镜）；
- 使用 1:1 或 4:3 固定比例容器 + 占位底色（LQIP 用主色），避免布局抖动；
- `alt` 必填，写"画面主体 + 动作 + 环境"，例如："国风漫画：秋夜旅店里，李白坐在床边，月光像白霜铺在地上，窗外一轮圆月"，不写"静夜思配图"这类无信息文本；
- 图片全部本地托管在 Pages，不依赖外部图床（避免防盗链与备案问题）。

### 5.6 成本与版权注意

- **诗作本身**为公有领域，可自由使用；**注释、译文、赏析、时间线文案必须原创**，不得直接搬运教材或教辅原文；
- AI 生成图需遵守所用工具的商用条款；公开站点应标注"**AI 辅助生成**"（页脚统一声明 + 图片 `credit` 字段），符合生成式 AI 内容标识要求；
- 避免在 prompt 中指名模仿特定艺术家/画师风格，降低侵权风险；
- 不使用真实人物照片或受版权保护的动画角色形象；
- 建议保留生成记录，出现争议时可证明来源与生成方式。

## 6. 内容规划

### 6.1 首期范围（结论）：36 首 = 30 首唐诗 + 6 首宋词

选择依据：

1. 覆盖小学语文教材高频篇目与《小学生必背古诗词 75 首》的核心交集；
2. 每个学段都有内容（低年级 10、中年级 10、高年级 10 + 宋词 6），家长按年级就能找到；
3. 36 首是"一个人能在一次迭代内完成注释、译文、拼音、配图、校对"的上限，超过这个量质量会崩；
4. 不做"全唐诗选集"式的宏大叙事，先把 36 首做到"每首都敢给孩子看"。

> 说明：宋诗（如《赠刘景文》《夜书所见》《饮湖上初晴后雨》《题西林壁》《示儿》《泊船瓜洲》）不放进"唐诗"或"宋词"，统一归入次期上线的 **其他朝代 → 宋代诗歌**，避免体裁分类混乱。首期不收录。

### 6.4 内容审核要点（针对小学生）

1. **题材尺度**：战争诗只讲"守边、想家、盼和平"，不描写杀戮；贬谪诗讲"想念家乡/朋友"，不讲政治斗争细节；宫怨、爱情词（如《鹊桥仙》）放高年级拓展并弱化情感描写；
2. **语言尺度**：译文用口语，句子 ≤25 字；避免"断肠""孤魂""白骨"等词直译，改为"心里很难过""非常想念"；
3. **学术严谨**：作者生卒年、地名今属、写作年代有异说时，用"约""一般认为"标注，不把一家之言写成定论（如《静夜思》"床"的释义）；
4. **不做戏说**：可以有趣（冷知识、漫画），但不能编造诗人对话、恶搞历史人物；
5. **版权**：注释、译文、赏析、时间线文案原创；引用教材原文需注明出处且控制在必要范围；
6. **一致性**：同一作者在不同作品页的简介、生卒年、称号必须一致，由构建脚本做交叉校验；
7. **敏感内容**：涉及民族、宗教、地域的内容回避；不出现真实学校、教师、儿童姓名；
8. **可读性**：每篇上线前由 1 名非专业成年人试读，标记"看不懂的句子"，全部改掉才算通过。

## 7. 技术选型与目录结构

### 7.1 结论：Astro（纯静态输出）+ JSON 数据 + GitHub Actions 发布

对比三种可行方案：

| 方案 | 页面维护 | 拼音/组件复用 | 首屏 JS | 构建复杂度 | 结论 |
|---|---|---|---|---|---|
| 纯手写 HTML | 100+ 页面需手工同步导航、上下首 | 复制粘贴，易不一致 | 0 | 无 | 否，内容一多必然失控 |
| Vite + 原生 JS 多页 | 需自己写多页入口与路由 | 中等 | 小 | 中 | 备选，但缺少内容校验与模板继承 |
| **Astro 静态输出** | 模板 + 数据驱动，新增一首诗 = 加 1 个 JSON | 组件化（PinyinText / Timeline） | 默认 0，交互按需 | 低 | **推荐** |
| Next/Nuxt | 过重，默认带运行时 | 好 | 大 | 高 | 否，静态内容站不需要 |

选择 Astro 的具体理由：

1. **默认零 JS**：拼音开关、译文展开只需少量内联脚本，首屏对家长手机最友好；
2. **内容集合 + Zod 校验**：构建时自动检查 JSON 字段、拼音长度、作者引用，错误直接让 CI 失败，避免脏数据上线；
3. **文件路由天然匹配四级 URL**，`getStaticPaths` 一次生成全部页面；
4. **构建产物就是纯 HTML/CSS/图片**，与 GitHub Pages 完全兼容，无服务端依赖；
5. 生态成熟，`withastro/action` 可直接对接 GitHub Pages。

**构建产物**：`dist/`，纯静态。**站点根路径**：`base: '/'`（自定义域名根），无需子路径适配。**CNAME** 放 `public/CNAME`，构建时自动复制到 `dist/CNAME`。

### 7.2 部署方式（结论：切换到 GitHub Actions）

现状是"main 分支根目录"发布，无法执行构建，因此必须二选一：

- **推荐**：Settings → Pages → Source 改为 **GitHub Actions**，由 workflow 构建 `dist/` 并发布；
- 不推荐"本地构建后把 dist 提交到 main 根目录"：会把源码和产物混在一起，历史膨胀，且容易忘记构建。

一次性改动（需你授权）：GitHub 仓库设置里切换 Pages Source，并提交 `.github/workflows/deploy.yml`。自定义域名与 DNS 不变，`CNAME` 文件继续生效。

`.github/workflows/deploy.yml` 建议内容：

```yaml
name: Deploy to GitHub Pages

on:
  push:
    branches: [main]
  workflow_dispatch:

permissions:
  contents: read
  pages: write
  id-token: write

concurrency:
  group: pages
  cancel-in-progress: true

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: withastro/action@v3
        with:
          node-version: 20

  deploy:
    needs: build
    runs-on: ubuntu-latest
    environment:
      name: github-pages
      url: ${{ steps.deployment.outputs.page_url }}
    steps:
      - id: deployment
        uses: actions/deploy-pages@v4
```

> 注意：`withastro/action` 默认执行 `npm install && npm run build` 并上传 `dist/`；若使用 pnpm 需显式配置包管理器。构建在 GitHub 侧完成，**本机无法访问 github.com 不影响部署**，只影响本地 push（需代理/镜像）。

| D5 | 首期是否做真人朗读音频 | **首期先用浏览器 TTS 降级，M4 再补真人/童声** | 音频制作与校对是独立成本，不阻塞上线 | 确认优先级 |
| D6 | 学段与教材依据 | 以**现行部编版（2024 修订）**为准，上线前逐条核对册次 | 教材篇目与册次会调整，不能凭记忆 | 确认是否有指定教材版本 |
| D7 | 宋诗归属 | 首期不收；次期放 **其他朝代 → 宋代诗歌** | 保持"唐诗/宋词"分类纯粹，避免一级菜单膨胀 | 确认 |
| D8 | 域名与 DNS | **保持不变**（up999.cn，A 记录指向 Pages） | 已生效且 HTTPS 正常，迁移无收益 | 知悉即可 |
| D9 | 本地仓库同步 | 需要你提供**可用代理或镜像**，或允许我用网页/压缩包方式同步 | 本机直连 github.com 超时，无法 push | 授权网络方案 |

### 9.2 主要风险

| 风险 | 影响 | 应对 |
|---|---|---|
| 拼音多音字出错 | 直接误导儿童，是最严重的内容事故 | 逐条人工锁定 + 二校 + 抽检；建立多音字规则表；上线后提供纠错入口 |
| 教材版本差异 | 册次、篇目、个别用字与家长期待不符 | 标注"以现行部编版为准"，每首写 `sources`；上线前逐条核对 |
| AI 配图质量不稳 | 手指、文字、时代错乱，影响信任 | 4 选 1 + 人工修整；统一角色设定；抽检不通过就重生成 |
| 内容工作量被低估 | 排期延误，偷工减料 | 按批次交付，每批独立验收；宁可少而精，不一次性铺 100 首 |
| Pages 发布方式切换 | 首次配置失败会导致站点短暂不可用 | 先在 PR/预览分支验证 Actions；切换前记录当前设置以便回退 |
| 本机网络受限 | 无法 clone/push，阻塞实施 | 使用代理/镜像；或由 GitHub 网页端上传；Actions 构建不受影响 |
| 图片体积膨胀 | 移动端加载慢，Pages 流量压力 | 预压缩 + WebP/AVIF + 懒加载；单页图片总量控制在 300KB 内 |
| 文案版权 | 搬运教辅导致侵权投诉 | 全部原创；引用教材仅限必要原文并注明；保留创作记录 |
| 过度"低幼化" | 高年级与家长觉得幼稚 | 分学段语气：低年级故事化，高年级保留赏析深度 |
| 无后端导致功能受限 | 无法收藏同步、学习记录 | 首期用 localStorage；确有需求再引入轻量后端或第三方服务 |

## 附录 A：内容校验规则（`validate-content.mjs`）

1. `slug` 全站唯一，仅允许 `[a-z0-9-]`；
2. `authorId`、`dynasty`、`era` 必须存在于对应索引；
3. `pinyin[]` 长度 = `text` 去标点后的字符数，且每项非空、只含合法拼音字符；
4. `notes[].id` 唯一，且至少被一条 `lines[].noteIds` 引用；`noteIds` 不得指向不存在的注释；
5. `storyline` 的 `step` 从 1 连续递增；`imageStep`（若有）必须能匹配到 `panels`；
6. `status=published` 时：`images.cover`、`translation`、`storyline`、`sources`、`writtenLabel` 必填；
7. `writtenYear` 为数字，允许负数（公元前）；同一作者内 `(writtenYear, orderInAuthor)` 不得重复；
8. `images.cover` 的 `src` 必须真实存在于 `public/`，且 `width/height/alt` 齐全；
9. 同一作者的 `name`、`birthYear`、`deathYear` 在所有作品引用中一致；
10. 文本中不得出现 TODO、待补、占位符（`xxx`、`【】`），避免半成品上线。
