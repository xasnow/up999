# 汉字搜索方案（纯前端 · 标题 + 作者）

> 状态：已实施（2026-11-28），本文档同时作为实现说明。
> 数据基线：467 首作品 / 133 位作者（当前 `src/data` 现状），标题与作者名字段 100% 有值。

## 0. 范围

- 输入：仅汉字，允许部分输入（1 字也可查）。
- 字段：只匹配**标题**与**作者名**，不检索正文、译文、注释。
- 形态：结果为列表，不要求唯一；纯前端静态实现，不新增后端。
- 触发：输入即搜，**不设搜索按钮**；索引在输入框获得焦点时预取。
- **空输入硬性规则**：输入框为空、或归一化后为空（只输入了标点/空格）时**不搜索**，只展示默认状态，不渲染任何结果列表。
- 明确不做：拼音/首字母缩写、繁体映射、热度排序、搜索统计。

## 1. 实测依据（决定阈值与交互的数字）

| 维度 | 实测 |

结论：纯汉字、标题+作者两个字段，规模上完全够用；真正的工程点是**归一化、作者折叠、同名消歧**，不是性能。

## 2. 匹配规则

### 2.1 标题归一化（索引侧与查询侧共用同一函数）

- 删除字符：`（ ） ( ) · ・ ， 。 ！ ？ 、 ； ： " " ' ' 《 》 〈 〉 「 」 【 】 — …` 以及所有空白字符。
- 其余字符原样保留（含「其一」「其二」「三首」「节选」这类汉字后缀，不做语义裁剪）。
- 每条作品存两份：`title`（展示原样）、`titleNorm`（匹配用）。**展示永远用 `title`**，归一化只影响匹配。
- 查询侧同样归一化；归一化后为空串时不触发搜索。

效果（实测口径）：
- 「悯农（其二）」→ 归一化「悯农其二」；用户输入「悯农其二」或「悯农（其二）」都能命中。
- 「无题·凤尾香罗薄几重」→「无题凤尾香罗薄几重」；「无题」仍命中 6 首。

### 2.2 标题匹配

`titleNorm.includes(qNorm)`，并记录命中位置 `idx`（用于排序第 3 层）。

### 2.3 作者折叠

- 作者名命中时，**只输出一条作者结果，不展开该作者作品列表**。
- 作者结果字段：姓名、朝代·时期、作品数（由索引统计）。点击进入作者页。
- 理由：不折叠时「李」= 10 作者（90 首）+ 10 标题 = 100 行，「王」= 63 行，「李白」= 45 行；折叠后分别是 20 / 17 / 4 行。

### 2.4 组合输入解析（作者 + 标题）

按顺序尝试，命中即停：

1. **无分隔连写**：从查询开头匹配作者全名（按作者名长度**降序**匹配，先「孟浩然」后「孟浩」），剩余部分非空且能在归一化标题中匹配到 ≥1 首 → 作者作为过滤条件，剩余部分作为标题查询。
2. **带空格**：按空白拆成两段，前段命中作者名、后段命中标题 → 同上。
3. **兜底**：整体按普通标题/作者匹配（含"标题含作者名"的情况）。

必须处理的边界：

- 「王维」「李白」这类查询，剩余部分为空 → **不启用规则 1**，按普通查询处理，否则会切成"作者=王维 + 空标题"。
- 11 首标题本身含作者名：只有剩余部分能匹配到标题时才按组合处理；否则保留普通匹配，并靠排序把作者卡放最前（见第 3 节 L0）。
- 示例：`李白静夜思` → 作者=李白 + 标题含「静夜思」→ 1 条；`李白` → 作者卡 1 张 + 杜甫的 3 条标题（排在作者卡之后）。

### 2.5 单字输入与分级展示

**不允许限制"最少两个字"**，原因是全站有 4 首单字标题作品，限制后它们无法通过标题搜索命中：

| 标题 | 作者 | 体裁 | 学段 | 教材 |
|---|---|---|---|---|
| 蝉 | 李商隐 | 五言律诗 | ext | 非教材 |
| 蜂 | 罗隐 | 七言绝句 | g1-2 | 部编版语文四年级下册 |
| 风 | 李峤 | 五言绝句 | g1-2 | 部编版语文一年级上册 |
| 画 | 王维 | 五言绝句 | g1-2 | 部编版语文一年级上册 |

其中 3 首是小学教材篇目，正是本站主要用户要查的内容；且「王」「李」这类单字是作者浏览的真实入口，限制后同样失效。

单字的代价集中在「其」50 条、「夜」「山」32 条、「送」30 条这类低区分度字上，因此采用**分级展示**：

- 查询长度为 1 时：作品最多展示前 **10** 条，作者卡最多 **6** 张，其余折叠为「共 N 条 · 查看全部」；用户点击后才展开全量。
- 查询长度 ≥2 时：全量渲染（p90 只有 2 条）。
- 单字总数 >20 时额外提示"输入更多字可精确查找"。
- 结构后缀（其一/其二/节选/三首）按普通中间命中处理，排序天然靠后，不做隐藏。

## 3. 排序层级

| 层级 | 规则 |
|---|---|
| L0 | 作者全名完全相等 → 作者卡（恒在标题结果之前） |
| L1 | 标题归一化后完全相等 |
| L2 | 标题前缀匹配 |
| L3 | 标题中间匹配（按 `idx` 升序） |
| L4 | 作者名前缀 / 中间 |

同层内的次序（全部是现成字段，无需新增数据）：

1. `textbook` 非空（教材篇目优先）
2. 学段：`g1-2` → `g3-4` → `g5-6` → `ext`
3. 有名句（`famousLines` 非空）
4. `no` 升序（仅作稳定排序键）

注意：`no` 是全局编号，**不是热度**；站内没有浏览量/评分数据，不做"热度排序"。

效果示例：「月」19 条中，九月九日忆山东兄弟、古朗月行（节选）、春江花月夜（节选）、六月二十七日望湖楼醉书 等教材篇目自然靠前。

## 4. 每条结果展示什么

标题结果（一行内可扫读）：

- 标题（原样，含「（其一）」「（节选）」「·词牌」）
- 作者
- 朝代 · 时期（如 唐诗 · 盛唐）
- 体裁 `form`（七言绝句 / 五言律诗 / 词（小令））
- 学段（一年级~二年级 / 拓展）
- 名句 `famousLines[0]`（8 组同名作品的名句全部不同，是成本最低的消歧信息）
- 教材标记（`textbook` 有值时显示，如"部编版语文四年级下册"）
- 命中字段标签：仅跨字段命中时显示「标题命中 / 作者命中」

作者结果：姓名、朝代 · 时期、作品数。

不展示：拼音、译文、赏析（信息密度过高，列表场景不需要）。

## 5. 触发方式与输入法保护

**输入即搜，不设搜索按钮。** 理由：本地检索一次只要 0.01ms，按钮没有性能收益；移动端软键盘会遮挡按钮，且输入法候选栏自带"搜索/确认"键。

中文输入法的关键事实与对应处理：

| 阶段 | 现象 | 处理 |
|---|---|---|
| 拼音组合中 | `input` 连续触发，`event.isComposing === true`，值是 `jing`、`jingyesi` 这类拉丁串 | 组合期间**不搜索**，并保留上一次结果，避免闪"无结果" |
| 候选上屏 | `compositionend` 触发，Chrome 后随一次 `input`（`isComposing=false`） | `compositionend` 后立即（约 10ms）执行一次搜索 |
| Android 部分输入法 | 不派发 composition 事件，只写入已上屏文本 | 用**ASCII 兜底**：归一化后不含汉字时视为"输入中"，不渲染结果/空态 |
| 连续输入 | 每敲一个字都要重渲染 | 防抖 **140ms**（取 120–150ms 区间），Enter/搜索键跳过防抖 |

其他实现约束：

- 输入框属性：`type="search"`、`autocomplete="off"`、`autocapitalize="off"`、`spellcheck="false"`、`enterkeyhint="search"`；不设置 `inputmode`，避免破坏中文键盘。
- 归一化后为空（空串/纯标点）→ 回到默认状态；归一化结果与上次相同 → 跳过重渲染。
- 结果数量用 `aria-live="polite"` 播报，焦点始终留在输入框。
- **索引预取**：输入框 `focus` 时（一次性）请求 `/search-index.json`，不在页面加载时请求，避免占用详情页/首页的 LCP 带宽；索引构建 2ms，用户敲第一个字时通常已就绪。

## 6. 必须处理的坑

| 坑 | 实测现象 | 处置 |
|---|---|---|
| 括号后缀 | `悯农其二` 原始标题匹配 **0 命中**，`悯农（其二）` 才 1 命中；`观书有感其二` 同样 0 | 标题归一化去括号后再匹配（2.1）；展示仍保留括号 |
| 同名作品 | 8 组重名；「隋宫」两条**同为李商隐**，只能靠七绝/七律区分；「悯农」其一/其二同作者同体裁，只能靠后缀 | 列表必须显示 `form` + 完整标题后缀；不要做"同名合并" |
| 标题含作者名 | 11 首；搜「李白」时杜甫的 3 首会混入，搜「王维」时孟浩然的《留别王维》排第一 | L0 作者卡置顶 + 显示命中字段标签；组合解析加"剩余非空"条件 |
| 繁体输入 | `靜夜思`、`春風` 均 **0 命中**，数据无繁体/异体字段 | 本期不支持；空结果时给出提示文案（"仅支持简体中文"） |
| 结构词 | 「其一」18 首、「节选」10 首、「三首」5 首，几乎无语义价值 | 结构词作为低优先级/降权词；不建议直接隐藏（用户可能就是想找"其一") |
| 标点 | 输入「·」命中 87 首 | 查询归一化后若只剩标点 → 视为空查询，不搜索 |
| 单字量级 | 最大 50 条（「其」），32（夜/山）、30（送）；另有 4 首单字标题作品 | 允许单字搜索，用「前 10 条 + 总数」分级展示（2.5），不做"最少两字"限制 |
| 作者展开 | 不折叠时「李」100 行、「王」63 行、「李白」45 行 | 作者命中一律折叠成卡片（2.3） |
| 组合歧义 | `李白静夜思` 纯子串 0 命中；标题含作者名的 11 首易误切 | 按 2.4 的三条规则顺序解析，作者名按长度降序匹配 |

```json
{
  "poems": [
    { "u": "/tangshi/shengtang/libai/jingyesi/", "t": "静夜思", "n": "静夜思",
      "a": "李白", "an": "李白", "au": "/tangshi/shengtang/libai/",
      "e": "唐诗·盛唐", "f": "五言绝句", "g": "g1-2", "tb": "部编版语文一年级下册",
      "q": "床前明月光，疑是地上霜。", "no": 1 }
  ],
  "authors": [
    { "a": "李白", "an": "李白", "au": "/tangshi/shengtang/libai/", "e": "唐诗·盛唐", "c": 42 }

```

体积实测：**137.1KB raw、gzip 34.3KB、brotli 26.8KB**；随作品数线性增长，不索引正文，因此不随长诗膨胀。
